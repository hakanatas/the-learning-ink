Note: the prompt mentions a reference image, but it never reached the session. The visual language was built from the written brief alone.

```text
PROJECT: THE LEARNING INK — How Artificial Intelligence Works
A Procedural Animated Educational Short Film

You are a senior creative coder, generative artist, animation director, JavaScript graphics engineer, and science educator.

Your task is to create a visually striking, fully animated short film that explains how artificial intelligence (specifically, a neural network) learns, using procedural JavaScript drawing.

The target audience is middle and high school students (ages 12–17) with no prior AI knowledge. The film must be emotionally engaging AND conceptually accurate. Every visual metaphor must correspond to a real mechanism in machine learning. Do not show "magic brains," glowing robots, or sci-fi clichés.

I have attached a reference image showing a minimalist black-ink animation on an off-white background. Use it to understand the visual language, but create an original animation with its own story, composition, and movement.

Do not create a slideshow, an infographic with moving arrows, or a simple particle demo. Build a genuine animated short film with evolving scenes, an expressive character, cinematic transitions, and continuous visual storytelling.

────────────────────────────────
1. TECHNICAL REQUIREMENTS
────────────────────────────────

Build the project using:
- JavaScript
- HTML5 Canvas 2D
- requestAnimationFrame for real-time playback
- Procedural geometry and vector-based drawing
- Bezier curves, paths, particles, and custom brush strokes
- Deterministic animation driven by a master timeline

All visual elements must be generated by JavaScript code.

Do not use:
- AI image- or video-generation APIs
- External images, pre-rendered video, or stock footage
- CSS-only animation
- Static illustrations disguised as animation

You may use lightweight libraries only if they meaningfully improve the result. Prioritize Canvas 2D.

────────────────────────────────
2. VISUAL DIRECTION
────────────────────────────────

Hand-drawn, minimalist, experimental ink animation:
- Warm off-white paper background with subtle grain
- Deep black ink illustrations
- Slightly imperfect hand-drawn outlines, variable line thickness
- Organic brush strokes, ink bleeds, and splashes
- Expressive silhouette-based character design
- Fluid, organic motion and cinematic composition

Visual encoding rules (keep them consistent throughout the film, because students will learn to "read" them):
- Neurons = small ink dots with a soft, bleeding edge
- Connections = brush lines. LINE THICKNESS = WEIGHT STRENGTH. Thin/broken lines = weak weights, thick confident strokes = strong weights
- Negative weights = dashed or hollow (double-outline) strokes
- A signal traveling forward = a dark ink pulse flowing along the line
- Error = an ink blot that cracks or smears
- Learning correction (backpropagation) = a pale, reverse-flowing wash that thickens or thins lines as it passes
- The ONLY color in the film is a warm amber accent (e.g. #E8A33D), used exclusively for the moment of correct generalization (Scene 6). Nowhere else.

Avoid generic tech motion graphics, glowing blue circuits, binary-code rain, and robot imagery.

────────────────────────────────
3. STORY: THE LEARNING INK (90 seconds)
────────────────────────────────

A tiny ink creature named "Nokta" is born knowing nothing. By looking at many examples, making mistakes, and being corrected, it slowly learns to recognize and then draw birds. The film is a metaphor for how a neural network is trained.

SCENE 1 — A BLANK MIND (0–8 s)
- Empty paper. A single ink droplet falls and lands in the center.
- It trembles, sprouts small brush strokes, and becomes Nokta: a small, round-bodied creature with thin legs and large eyes.
- Inside its semi-transparent head, a faint, TANGLED web of thin lines and dots is visible: a network with random weights.
- Nokta opens its eyes and looks around. The camera slowly pushes in.

SCENE 2 — DATA (8–20 s)
- Hand-drawn sheets drift down like leaves. Each has a simple procedural ink sketch: birds and fish, in many different poses, sizes, and styles (all procedurally varied, no two identical).
- Each sheet has a small hand-drawn label symbol in the corner (a bird glyph or a fish glyph). These are the LABELS.
- A large, gentle human hand silhouette (drawn in loose ink) places the sheets in front of Nokta. This subtly communicates that humans create and label the data.
- Nokta looks at the first bird drawing. The lines in its head fire randomly. It points confidently at the FISH glyph. Wrong.
- An ink blot appears and cracks: the ERROR. Nokta flinches (squash, anticipation, recoil).

SCENE 3 — INSIDE THE MIND (20–36 s)
- The camera dives through Nokta's eye into its head. Cinematic zoom with depth layers.
- The tangle unfolds into a clear layered structure: an input layer (dots arranged like the pixels of the bird drawing), 2 hidden layers, and 2 output nodes (bird / fish).
- Show ONE neuron in close-up: several lines of different thickness bring pulses in. The pulses pool inside the dot (weighted sum), and when the ink level passes a threshold line, the neuron fires its own pulse forward (activation).
- Pull back and show the full FORWARD PASS: the bird drawing dissolves into input dots, pulses ripple layer by layer, and the wrong output node (fish) fills with ink.

SCENE 4 — LEARNING FROM MISTAKES (36–54 s)
- The error blot at the output releases a pale wash that flows BACKWARD through the network (backpropagation).
- As the wash passes each connection, lines visibly thicken or thin. Connections that caused the mistake weaken, and helpful ones strengthen.
- Transition: the camera tilts and the network morphs into an ink LANDSCAPE of hills and valleys (the loss landscape). Nokta appears standing high on a hill.
- Nokta feels the slope under its feet and takes small, careful steps downhill (gradient descent). Each step matches one training example. Occasionally it overshoots a small valley and scrambles back (learning rate).
- Montage, accelerating: many sheets fly past, forward pulses, backward washes, steps down the hill. A small hand-drawn tally or curve in the corner shows the error decreasing.
- Return to the network: the tangled mess has become organized and purposeful, with clear thick pathways.

SCENE 5 — PATTERNS EMERGE (54–68 s)
- Travel through the trained layers from input to output.
- First hidden layer: neurons now "see" simple strokes (short lines, curves, corners), drawn as tiny ink fragments next to each node.
- Deeper layer: these fragments combine into parts (a wing, a beak, a fin, a tail).
- Output layer: parts combine into the concept "bird."
- Key visual: the same strokes assemble hierarchically, from simple to complex, like building blocks of ink.

SCENE 6 — THE FIRST CORRECT GUESS (68–80 s)
- Back outside. The human hand places a NEW drawing Nokta has never seen: an unusual bird (a different pose and style).
- Stillness. Nokta studies it. Pulses travel through the now-clear pathways.
- The bird output node fills, and a small warm AMBER light appears in Nokta's hand: the only color in the film. This is GENERALIZATION.
- Nokta releases the light. It expands as a circular wave, and the scattered sheets reorganize into neat groups (birds together, fish together).
- Nokta then picks up a brush and, stroke by stroke, draws its own bird. It predicts each next stroke based on the previous ones. This hints at generative AI.

SCENE 7 — LIMITS & ENDING (80–90 s)
- The hand places one final strange drawing: an abstract shape unlike anything in the data. Nokta confidently declares "bird," and a tiny crack appears. The message is: AI only knows the patterns in its data, and it can be confidently wrong.
- Nokta looks up at the human hand. The hand and the creature face each other for a quiet beat (a human in the loop).
- The camera slowly pulls back. The entire scene (network, landscape, sheets, Nokta) shrinks into a single small ink drawing on the original empty paper.
- Fade to off-white. End.

────────────────────────────────
4. EDUCATIONAL LAYER
────────────────────────────────

- Add optional minimal on-screen captions, hand-lettered in style and appearing/disappearing with ink-bleed transitions. Maximum 6 words each, 1 per key concept:
  Scene 2: "Veri / Data", "Etiket / Label"
  Scene 3: "Nöron / Neuron", "Ağırlık / Weight"
  Scene 4: "Hata / Error", "Geri yayılım / Backpropagation", "Gradyan iniş / Gradient descent"
  Scene 5: "Örüntüler / Patterns"
  Scene 6: "Genelleme / Generalization"
  Scene 7: "Veri kadar iyi / Only as good as its data"
- Captions can be switched between OFF / Turkish / English / Bilingual.
- Store all caption text and timings in one editable data file (captions.js). Also export them as an .srt subtitle file, so a teacher can add voice-over later.
- Leave gentle pacing gaps (beats) after each concept, suitable for adding narration.
- Accuracy check: before finalizing, review every scene and confirm the metaphor matches the real mechanism (weighted sum, activation threshold, forward pass, loss, backpropagation, gradient descent, feature hierarchy, generalization, out-of-distribution failure). List this mapping in the README.

────────────────────────────────
5. ANIMATION QUALITY REQUIREMENTS (most important)
────────────────────────────────

Every scene must contain real animation.

The character (Nokta) must have:
- Procedurally animated walking, careful stepping, and scrambling
- Expressive body language (curiosity, confusion, frustration, determination, joy)
- Head and body rotation, eye direction, and blinking
- Squash and stretch, anticipation, and follow-through
- Smooth pose transitions

The network and environment must have:
- Organic growth and reorganization (tangled → structured)
- Continuous subtle motion (breathing lines, drifting ink)
- Non-repetitive procedural variation, e.g. every data sketch is unique
- Smooth morphing between representations (network ↔ landscape ↔ drawings)

Virtual camera: position, zoom, rotation, smooth tracking, cinematic easing, and depth layers/parallax. Include one dramatic dive (Scene 3) and one slow reveal (Scene 7).

Choreograph deliberately around the story. Do not rely on random motion.

────────────────────────────────
6. TIMELINE & RENDERING ARCHITECTURE
────────────────────────────────

- A centralized master timeline. Every visual state is a pure function of time.
- Implement renderFrame(time) that renders the correct frame for any timestamp.
- Seeded randomness only. The same timestamp must always produce the identical image.
- No dependence on previously rendered frames. The network's "training progress" must be computed from time, not accumulated.
- Scene definitions live in separate editable modules (scenes/scene1.js …) with start/end times.

Target specs: 1920×1080, 16:9, 30 FPS, 90 seconds.
Provide a switch for 1080×1920 vertical format (recompose the camera, not just crop).

────────────────────────────────
7. PREVIEW & CONTROLS
────────────────────────────────

Local web interface with:
- Play / pause / restart
- Timeline scrubber with scene markers
- Jump to scene
- Playback speed (0.25× – 2×)
- Horizontal / vertical format switch
- Caption mode switch (Off / TR / EN / TR+EN)
- Display of the current timestamp, scene name, and the concept being taught

────────────────────────────────
8. VIDEO EXPORT
────────────────────────────────

- Deterministic frame-by-frame export to a high-quality MP4 (H.264).
- Use a headless browser (e.g. Puppeteer/Playwright) + FFmpeg, or an equivalent frame-sequence pipeline.
- Do not rely on real-time screen recording.
- Provide a single export command, e.g. `npm run export -- --format=horizontal --captions=tr`
- Also export the matching .srt file.

────────────────────────────────
9. DEVELOPMENT PROCESS
────────────────────────────────

Work in stages. Do not produce one giant untested file.

1. Project architecture, Canvas engine, deterministic timeline, seeded RNG
2. Reusable ink-brush and paper-texture system
3. Character rig and animation system for Nokta
4. Reusable neural-network drawing module (nodes, weighted lines, forward pulses, backward washes, tangled↔structured morph)
5. Build Scene 1 as a complete visual prototype. Run it, render screenshots at several timestamps, and inspect them.
6. Then build the remaining scenes one by one, testing each at multiple timestamps.

After each stage check for: rendering errors, broken transitions, inconsistent character proportions, visual-encoding inconsistencies (e.g. a thick line that suddenly means something else), and performance issues. If a scene looks simplistic or the concept is unclear, improve the drawing and choreography.

────────────────────────────────
10. DELIVERABLES
────────────────────────────────

- Complete JavaScript source code
- Working local preview
- Editable scene definitions and caption file
- Reusable character animation system
- Reusable procedural ink-drawing and neural-network drawing modules
- MP4 + SRT export pipeline
- README with run instructions and a "Metaphor → Real AI Concept" table

The final result must be a functioning, emotionally engaging animated film that a teacher can show in class. It must not be a technical demo.

Start with the core engine and Scene 1. Once the prototype works, continue with the remaining scenes.
```
